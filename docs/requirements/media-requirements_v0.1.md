## 0. 共通テンプレート（全媒体が満たす形）

各媒体は以下を必ず定義する:

- **接続経路**: MCP / ブラウザ(Playwright/Camoufox) / REST / コード生成 のいずれか＋フォールバック
- **アクション集合**: 作成・公開・応答・取得（媒体ごとに部分集合）
- **証跡**: 公開 URL / スクショ / エクスポートファイルhash / API レスポンス のうち取得必須のもの
- **KPI寄与**: 露出 / マイクロCV / 転換 / 関係 / 収益 のどの層のどのノードへ入るか
- **ワークフロー**: 割り当てる TAKUMI 由来スキル（カタログから）
- **ゲート**: 通過必須のゲート（企画↔品質・PR表記・倫理・金銭 等）
- **安全**: レート・承認要否・攻略地図の要否。各媒体の「レート」は BR-F5
  （ランダム化操作間隔・媒体別上限・アカウント保全）に従う — 全媒体共通の業務要求であり媒体側で緩和できない

該当しない観点は省略せず **「N/A（理由）」と明記**する（明示 N/A disposition）。

## 1. オウンドメディア

### 1.1 WordPress（略号 WP）

- **接続**: REST API（Application Passwords）主 ＋ WP-CLI（構築系）。ローカル Docker で検証
- **アクション**: 記事作成/更新/下書き/公開、メディアアップロード、カテゴリ・タグ管理、
  カスタム投稿タイプ操作、子テーマ・プラグイン配備（WP-CLI）、パーマリンク・SEO 設定
- **証跡**: 投稿 URL、REST レスポンス（投稿ID・リビジョン）、公開時スクショ、commit hash（原稿ソース）
- **KPI寄与**: 露出（PV・検索流入）、マイクロCV（記事内 CTA クリック・資料DL）
- **ワークフロー**: seo-jp, copywriting, content-design, design-evidence-jp, web-design
- **ゲート**: 企画↔品質（公開前 critic PASS 必須）、PR表記（アフィリエイト記事）、ゼロ広告費
- **安全**: 公開は束縛承認→オート移行。REST 書き込みは成立ペアID必須（FR-44）
- **MR-WP-1** 記事公開は下書き作成→審査→ペア成立→公開の順で、審査未了の直接公開経路を持たない
- **MR-WP-2** メディアは WP に一元保管し、SQLite は URL/ID 参照のみ（BR-G2）
- **MR-WP-3** テーマ解析結果（フック・テンプレート階層・スタイル体系）を playbooks に構造化保存
- **MR-WP-4** ポッドキャスト RSS を WP から配信できる（§4.2 と連携）
- **MR-WP-5**（レート・BR-F5）: 自サイトへの機械間 API のためランダム間隔は N/A。ただし REST 書き込みは
  バースト上限 30 req/分・公開 10 件/日（C: `rate.wp.*`）を守り、自サイトの可用性に負荷をかけない

## 2. SNS（ブラウザ突破・媒体別攻略地図）

### 2.1 X（略号 X）

- **接続**: ブラウザ（Playwright→検知時 Camoufox）。API 不使用
- **アクション**: ポスト投稿、スレッド投稿、画像/動画添付、リプライ応答、インプレッション取得
- **証跡**: ポスト URL、投稿確認スクショ、個別ポストのインプレッション/エンゲージ数値（画面値）
- **KPI寄与**: 露出（個別ポストのインプレッション）、関係（個別ポスト画面値から算出するエンゲージ率）。
  プロフィールアクセス等の全体アナリティクスは Premium 専用のため計測対象外（§99-5 決定）
- **ワークフロー**: sns-jp, copywriting, breakout-content-jp, engagement-reply-jp
- **ゲート**: 企画↔品質、倫理、ゼロ広告費（プロモ投稿禁止）
- **安全**: 日次投稿レート・応答レート（C）、攻略地図必須、投稿は承認→オート
- **MR-X-1** 日次回転（媒体特性）に対応し、スプリント長を他媒体と独立設定できる
- **MR-X-2** リプライ応答は engagement-reply ワークフローで、倫理ゲート通過後のみ送出
- **MR-X-3**（レート・BR-F5）: 検知リスク高。書き込み間隔 2〜8 秒の一様乱数、投稿 5 件/日・
  リプライ 10 件/日（C: `rate.x.*`）。警告・CAPTCHA 頻発時は間隔範囲を自動で広げ、凍結兆候で操作停止（RSK-01）

### 2.2 note（略号 NOTE）

- **接続**: ブラウザ。API なし
- **アクション**: 記事投稿、有料記事/マガジン作成・価格設定・販売状況取得
- **証跡**: 記事 URL、公開スクショ、販売数・売上（収益系）
- **KPI寄与**: 露出（ビュー・スキ）、収益（有料記事売上）
- **ワークフロー**: storytelling, sales-writing, copywriting, content-design
- **ゲート**: 企画↔品質、金銭（価格設定は束縛承認）、PR表記
- **安全**: 価格変更は常時人間承認（FR-26）
- **MR-NOTE-1** 有料コンテンツの価格設定・変更は金銭 escalation 対象
- **MR-NOTE-2**（レート・BR-F5）: 書き込み間隔 1〜5 秒の一様乱数、記事投稿 2 件/日（C: `rate.note.*`）

### 2.3 YouTube（略号 YT）

- **接続**: ブラウザ（アップロード・メタ設定）。Studio の分析はエクスポート取得
- **アクション**: 動画アップロード、タイトル/説明/タグ/サムネ設定、公開/限定公開、コメント応答、
  アナリティクスエクスポート
- **証跡**: 動画 URL、公開スクショ、再生数・視聴維持率・登録者増
- **KPI寄与**: 露出（再生数・インプレッション）、関係（登録者・コメント）
- **ワークフロー**: video-script, storytelling ＋ 制作パイプライン（Remotion/VOICEVOX）
- **ゲート**: 企画↔品質、倫理、ゼロ広告費
- **安全**: アップロードは承認→オート。長時間処理のため非同期タスク化
- **MR-YT-1** 動画 1 本の制作は台本→音声→素材→合成の制作パイプライン（FR-53）を経由
- **MR-YT-2** ショート（9:16）版を同一素材から ffmpeg プロファイルで派生生成できる
- **MR-YT-3**（レート・BR-F5）: Studio 操作の書き込み間隔 2〜8 秒の一様乱数、アップロード 2 件/日・
  コメント応答 10 件/日（C: `rate.yt.*`）。アップロードは非同期のため完了待ちはレート対象外

### 2.4 Instagram（略号 IG）

- **接続**: 公式 Graph API（無料・プロアカウント。ADR-006/§99-1）。ブラウザは attended 補助のみ
- **アクション**: フィード投稿、リール投稿、画像/動画添付、キャプション・ハッシュタグ、インサイト取得
- **証跡**: 投稿 URL、スクショ、リーチ・保存・エンゲージ数値
- **KPI寄与**: 露出（リーチ・インプレッション）、関係（保存・フォロワー）
- **ワークフロー**: sns-jp, breakout-content-jp ＋ 画像/リール制作
- **ゲート**: 企画↔品質、倫理、ゼロ広告費
- **安全**: API 経由（検知リスクなし）。日次上限は config で管理
- **MR-IG-1** ビジュアル主媒体のため design-evidence 審査（コントラスト・可読性）を品質ゲートに含む
- **MR-IG-2**（レート・BR-F5）: Graph API 経由は API quota 準拠（人間相当のランダム間隔 N/A）。
  投稿 3 件/日（C: `rate.ig.*`）。attended ブラウザ補助時のみ間隔 5〜15 秒の一様乱数を適用

## 3. コミュニティ

### 3.1 Discord（略号 DC）

- **接続**: 公式 MCP または Bot（優先）＋ブラウザ補完

- **証跡**: メッセージ URL/ID、投稿ログ、アクティブメンバー数・発言数
- **KPI寄与**: 関係（DAU/WAU・発言数・定着率）、転換（コミュニティ経由の CV）

- **MR-DC-3**（レート・BR-F5）: MCP/Bot は API quota 準拠（ランダム間隔 N/A）。投稿・応答は

## 6. プッシュ型配信

### 6.1 メルマガ / HubSpot（略号 HS）

- **接続**: 公式 MCP 主＋ブラウザ補完
- **アクション**: コンタクト管理、フォーム/LP のリード取得、リスト配信、開封/クリック取得。CRM 全般
- **証跡**: 配信 ID、送信数、開封/クリック率、リード獲得記録
- **KPI寄与**: 転換（リード数・フォーム完了率）、関係（開封・クリック）
- **ワークフロー**: sales-writing, copywriting, messaging-design-jp, retention 系
- **ゲート**: 企画↔品質、倫理、金銭（有料商品案内）
- **安全**: 月 2,000 通上限監視（C）、超過で停止＆再検討トリガー。法規は NFR-9
- **MR-HS-1** ナーチャリング自動化は HubSpot 有料機能を使わずハーネスループが SQLite 判定で駆動
- **MR-HS-2** リード受け皿（診断ツール・資料DL・LP フォーム）を集約し転換系 KPI の起点にする
- **MR-HS-3** 配信はオプトイン済みコンタクトのみを対象とし、全メールに配信停止導線を含むことを
  公開ゲートで機械検証する（特定電子メール法・NFR-9）。リード個人情報は HubSpot 側に置き、
  SQLite へは ID・スコア等の非個人情報のみ同期する（APPI）
- **MR-HS-4**（レート・BR-F5）: MCP は API quota 準拠（ランダム間隔 N/A）。配信は月 2,000 通の
  無料枠内で計画的に配分（C: `rate.hs.*`）。ブラウザ補完時のみ間隔 1〜5 秒の一様乱数を適用

### 6.2 LINE 公式アカウント（略号 LINE）

- **接続**: Messaging API（無料・公式。ADR-006/§99-2）。管理画面は attended 設定作業のみ
- **アクション**: セグメント配信、リッチメッセージ、友だち管理、配信結果取得
- **証跡**: 配信スクショ、到達/開封/ブロック数
- **KPI寄与**: 関係（開封・クリック・ブロック率）、転換
- **ワークフロー**: messaging-design-jp, psych-nudge-jp
- **ゲート**: 企画↔品質、倫理（プッシュの節度）
- **安全**: 月 200 通上限のため**全体一斉禁止・セグメント配信専用**。見込み度判定は SQLite/HubSpot データ
- **MR-LINE-1** 配信対象は必ずセグメント抽出（見込み度スコア）を経る。無差別一斉配信を構造的に禁止
- **MR-LINE-2** 配信は友だち登録（オプトイン）済みのみ。ブロック率を関係 KPI で監視し、
  閾値（C）超過で当該セグメント配信を停止する（NFR-9）
- **MR-LINE-3**（レート・BR-F5）: 管理画面のブラウザ操作は間隔 2〜8 秒の一様乱数。配信は月 200 通の
  無料枠から逆算し週 1 回・1 セグメント以内を既定とする（C: `rate.line.*`）

## 7. 収益・決済

### 7.1 Stripe（略号 STRIPE）

- **接続**: 公式 MCP 主
- **アクション**: 商品/価格作成、決済リンク/Checkout 発行、WP 埋め込み、売上照会
- **証跡**: 決済リンク URL、取引 ID、売上額（収益系）
- **KPI寄与**: 収益（売上・購入数・客単価）
- **ワークフロー**: offer-design-jp, sales-writing
- **ゲート**: 金銭（価格変更・返金・決済設定＝束縛承認、常時）
- **安全**: 手数料以外の固定費ゼロ。金銭操作は全て escalation
- **MR-STRIPE-1** 決済リンク発行までは自走可、価格/返金/設定変更は常時人間承認（FR-26）
- **MR-STRIPE-2**（レート・BR-F5）: 公式 MCP/API のため N/A（API quota 準拠。人間相当偽装は不要かつ不適切）

### 7.2 アフィリエイト / ASP（略号 AFF）

- **接続**: ブラウザ（読み取り限定）。**楽天は自動操作対象外**（規約明示禁止・§99-8 決定 2026-07-31）
- **アクション**: 自動化は成果レポート取得（A8/もしも/Amazon）の低頻度読み取りのみ。
  案件検索・提携申請は attended、リンク発行・WP 埋め込みは制作パイプライン側で完結。楽天は手動運用
- **証跡**: 提携状態、リンク、成果/報酬レポート（収益系）
- **KPI寄与**: 収益（アフィリエイト報酬）、記事単位の露出→クリック→成果歩留まり
- **ワークフロー**: sales-writing, ad-compliance-jp
- **ゲート**: **PR表記必須**（表記なしは公開不可・FR-24）、企画↔品質、倫理
- **安全**: ステマ規制遵守を機械ゲート化
- **MR-AFF-1** アフィリエイトリンクを含む成果物は PR 表記ブロック検証に合格しない限り公開ゲートを通過しない
- **MR-AFF-2** 成果レポートを記事単位で紐づけ、どのコンテンツが収益化したかを追跡
- **MR-AFF-3**（レート・BR-F5）: 自動操作は読み取り（成果レポート取得）のみ・低頻度（C: `rate.aff.*`、
  暫定 1 回/日）。書き込み系（提携申請等）は自動化対象外（attended）のためレート規定なし。
  楽天は自動操作対象外（§99-8）
