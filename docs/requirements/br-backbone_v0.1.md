# 業務要求（BR）背骨 v0.1

> status: **draft**（AI 起草 2026-07-30。人の承認で confirmed）
> 位置づけ: charter（層外 anchor）から降ろした共通の背骨。スライスごとの要求はここを参照して個別に書く。
> 各 BR は trace 用 ID を持つ。値はハードコードしない — 充填経路（H=ヒアリング / R=リサーチ / C=config）を明記。

## A. ループ駆動（外殻）

- **BR-A1** 三重ループ（上位=ブランド成長 / 下位=媒体スプリント / タスク内検証マイクロループ）を状態機械として駆動できること。回転の開始・進行・完了はすべて SQLite 上の状態遷移で表現され、prose の申し送りを持たない
- **BR-A2** 下位ループは媒体ごとに独立したサイクル長で並走できること（同期強制なし）。サイクル長は行動計画が定める（充填: R+C）
- **BR-A3** ブランド計画（1 年地平）を上位ループの北極星として保持し、全行動計画がこれに trace できること
- **BR-A4** タスクはループステップが発行し、ワークフロー 1 本を割り当てられ、検証マイクロループの PASS でのみ完了すること。リトライ上限（充填: C）で上位へエスカレーション

## B. ペアゲート・証跡

- **BR-B1** 企画↔品質ペア: 企画情報（訴求・ターゲット・狙い）と審査 PASS が対で SQLite に揃うまで、コンテンツは公開可能にならないこと（片肺禁止）
- **BR-B2** 計画↔計測ペア: KPI 目標と計測スナップショットが対で揃うまでスプリントレビューが成立せず、上位還流も発生しないこと
- **BR-B3** すべての完了判定は証跡（公開 URL・計測値・審査記録・commit hash・スクショ/ファイルハッシュ）の DB 収束を要件とすること。宣言のみの完了は構造的に不可能であること
- **BR-B4** 検証は作成者と別のエージェントが行うこと（自己審査禁止・P4）

## C. 機械ゲート（fail-close）

- **BR-C1** ゼロ広告費ゲート: 広告出稿・課金経路への遷移、および CAC/ROAS 等の有料指標の KPI 登録を機械的に遮断すること（fail-close）
- **BR-C2** PR 表記ゲート: アフィリエイト・PR コンテンツに広告表記が自動挿入され、表記なしでは公開ゲートを通過しないこと（ステマ規制遵守）
- **BR-C3** 倫理ゲート: 恐怖訴求・偽の希少性・不安増幅の心理術は審査で却下されること（P5）
- **BR-C4** 金銭操作（価格変更・返金・決済設定変更）はオートモード移行後も人間の束縛承認を要すること（escalation 境界）

## D. 三エンジン（型×動的充填）

- **BR-D1** ヒアリングエンジン: 事業前提・受入基準スキーマの不足スロットを検出し、構造化問診を生成して人に照会し、回答で充填できること
- **BR-D2** リサーチエンジン: KPI ツリー初期形・業種/媒体標準指標・運用詳細を Web 検索で取得し起草できること。外部照合で幻覚を抑止すること
- **BR-D3** 設定管理: 安全側数値（支出上限・レート・リトライ上限・オート移行基準）を config として SQLite に保持し、変更を証跡化すること
- **BR-D4** ハーネスは事業非依存であること。別ブランド・別事業の追加が型の再充填のみで可能なこと

## E. KPI ツリー・計測

- **BR-E1** KPI ツリーは露出→マイクロ CV→転換→関係→収益の階層を持ち、全媒体の実測がノードに紐づくこと。媒体横断集計（将来のオーガニック版 MMM）を見越したスキーマであること
- **BR-E2** 計測取り込みはブラウザエクスポート（GA4・Search Console・各 SNS・ASP・KDP・Stripe/note）→ パース → SQLite 時系列投入で行い、取得証跡（ファイルハッシュ・スクショ）を残すこと
- **BR-E3** ダッシュボードは SQLite から HTML を自動生成すること（主）。xlsx エクスポート（従）を提供すること

## F. 接続・媒体

- **BR-F1** 外部接続は MCP → ブラウザ自動化 → 有償 API（明示的例外のみ、現状 Seedance）の優先順で選定されること。例外の支出は台帳化されること
- **BR-F2** ブラウザ自動化は攻略地図（サイト構造・手順）を DB に蓄積し、破損検知時は自己修復を試み、失敗時はエスカレーションすること
- **BR-F3** 媒体・能力の追加は外殻に触れずワークフロー追加で行えること
- **BR-F4** 認証情報（ログインセッション・アプリケーションパスワード）はリポジトリに置かず、安全に保管・更新されること（HELIX 同様の鍵分離）

## G. 制作・資産

- **BR-G1** 制作はコード×ブラウザレンダリングを主軸とし、成果物のソースを git ワークスペースで版管理し、審査 PASS 版を commit hash で特定できること
- **BR-G2** コンテンツ実体（テキスト・画像・動画・音声）は WordPress に資産として収束し、SQLite からは参照のみとすること。資産のリパーパス（記事→SNS/スライド/音声/動画/EPUB）が追跡できること
- **BR-G3** ブランドデザインシステム（Claude Design 正本）のトークンが全制作物に適用されること
- **BR-G4** WP 開発は既存テーマ解析＋子テーマ/プラグイン拡張で行い、解析結果を攻略地図として残すこと

## H. 承認・自律

- **BR-H1** 企画確定以降はヒューマンアウトオブループであること。人への照会はヒアリングエンジン経由と束縛承認のみ
- **BR-H2** 外部公開は経過措置としてスマホ（Claude Code アプリ通知）束縛承認を要し、安定稼働基準（充填: C）の証跡が揃い次第オートモードへ移行できること
- **BR-H3** ループ・タスクの異常（ゲート赤・予算超過・攻略地図破損）は検知され、安全に停止または人へ通知されること
