# ADR-011: 媒体・外部接続の実装前 PoC を必須化する

- status: proposed
- date: 2026-08-13
- decision_authority: PO（未承認 — 本 ADR は提案ドラフト。必須化の指示自体は PO 2026-08-13）
- 関連: ADR-008 v0.2（媒体縦切り・文化圏帯）、ADR-002（接続優先順位）、ADR-003（ブラウザ三段）、
  br-media（媒体調査正本）、FR-74〜77（ブランド/アカウント統合）

## 背景

1. 各媒体の運用は「ミニ HARNESS」になる（媒体ごとに調査→検証→設計→実装→運用の自分の
   V 字を持つ）。全体設計（kernel・契約・ゲート）は L0〜L6 で確立済みだが、媒体固有の
   不確実性 — 接続経路の実挙動・レートの実値・規約運用の実際・UI/エクスポートの実態 — は
   机上の調査（BR-M）だけでは潰せない。
2. WordPress で先行実証済み: 本実装前に使い捨てリポ（poc-wp）で採否基準 5 件を先に定義し、
   P0〜P4 の貫通検証を evidence で判定して採用した。この工程が契約の欠陥を実装前に露見させた。
3. V1 帯だけでも PoC を要する媒体が複数見えている（note のブラウザ車線・HubSpot 無料枠実挙動・
   X の API 実レートと複数アカウント運用・LINE の通数管理）。

## 決定（提案）

1. **リリース段階単位の設計前 PoC を必須化**: PoC の単位は ADR-008 のリリース段階
   （V1／V2／V3 各帯の媒体単位の段階）とする。各段階で、その段階の詳細設計（L3 の当該媒体
   契約の confirmed 化・L4 以降の設計着手）より**前に** PoC の完了を必須とする。
   全てを先に厳格に設計するのではなく、**PoC で検証 → 判断 → 判断結果を設計として書く**
   順序を既定とする（poc-wp → L3 FR-74〜77 起票がこの順序の実例）。
   PoC なしの段階設計・実装着手は差戻し。
2. **PoC の型**（poc-wp を標準形とする）:
   - 採否基準を PoC 開始前に文書で定義する（後出しの基準変更は不採用側にのみ許す）
   - 使い捨ての専用リポ `poc-<media>` で実施し、製品リポ（本リポ・src/helix/）を汚さない
   - 検証は縦切り貫通（認証→投稿→検証→KPI 回収の 4 面契約の実地確認）を含む
   - 判定は evidence（JSON/スクショ/ログ）で行い、PoC リポに保存する
   - 資格情報は PoC でも本番規律に従う（600 権限・リポ外・ブランド名前空間）
3. **PoC の出口は 3 値**: 採用（→ L3 起票・設計へ）／不採用（理由と evidence を BR-M へ
   反映）／条件付き保留（blocker を明記 — 例: TikTok の audit 要件）。
   いずれも結果を br-media の当該チャネルの structure（外形事実）へ反映する。
4. **PoC で検証したアカウント・経路は brand × media × account 台帳（FR-74）の初期行へ昇格**
   できる（PoC evidence が台帳の根拠になる）。
5. **例外**: PoC の省略は閉じた理由語彙でのみ許す（自由記述禁止）。語彙 =
   `実運用実績あり:`（同一 service・同一経路で実運用 1 サイクル完走済み）／
   `PoC 済み接続の小変更:`（同一 service の endpoint・operation 追加）／
   `読み取り専用:`（write を含まない接続で、レート節度が config 化済み）。
   省略判断は当該媒体の BR-M structure（外形事実の追記）に理由語彙付きで記録する。

## 帰結

- 媒体採用パイプラインが確定する: **BR-M 調査 → PoC（採否基準先行定義・evidence 判定）→
  判断 → 設計（L3 起票）→ 実装 → 実運用 1 サイクル完走**（最後の完了定義は ADR-008 のまま）
- 段階の詳細設計は PoC の判断結果を書き起こす形になる（机上先行の全面設計をしない。
  kernel・共通契約など媒体非依存の設計は本 ADR の対象外 — 従来どおり）
- V1 帯の各段階（note／HubSpot／X／LINE 等）は設計前に `poc-<media>` を実施する
- ゲート化は S1 で検討する（例: 媒体 slice の設計 confirmed 化に PoC evidence への参照を
  要求する G-POC-EVIDENCE。本 ADR 時点では規律のみ先行）

## 未決事項（PO 判断）

1. PoC の標準採否基準テンプレート（poc-wp の 5 基準を一般化するか、媒体ごとに全定義するか）
2. G-POC-EVIDENCE ゲートの導入時期（S1 か、最初の媒体 PoC 完了時か）
